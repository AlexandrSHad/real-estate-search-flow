Sreality.cz listing API — field reference
5 624 listings in sample 22 results per page
Each item in results[] — the core property identification and classification fields.
id
number Unique listing ID. Used to construct the detail URL: sreality.cz/detail/…/{id}
e.g. 3993514828
name
string Auto-generated listing title — offer type + property type + area + land size.
"Prodej rodinného domu 190 m², pozemek 995 m²"
categoryMainCb
object Main property category. {name, value}
1 = Byty (Flats)2 = Domy (Houses)3 = Pozemky (Land)4 = Komerční (Commercial)5 = Ostatní (Other)
categorySubCb
object Sub-category within the main type. {name, value}
33 = Chata (Cottage)37 = Rodinný (Family house)39 = Vila (Villa)54 = Vícegenerační (Multi-gen)
categoryTypeCb
object Offer type. {name, value}
1 = Prodej (Sale)2 = Pronájem (Rent)
discountShow
boolean Show a price-reduction badge on the listing card. true = price was lowered recently.
watchdogBadge
string Badge for saved-search (watchdog) subscribers.
nonenew = first seen update = price/data changed
hasMatterport
boolean Listing includes a 3D virtual tour (Matterport).
hasVideo
boolean Listing includes a video walkthrough.
All monetary values are in CZK. A value of 0 means "price on request" (cena na vyžádání).
priceCzk
number Total price in CZK. For rentals, this is the monthly rent. Zero = price on request.
e.g. 6500000 → 6 500 000 Kč
priceCzkPerSqM
number Price per m² in CZK, derived from total price ÷ usable area. Useful for quick cross-listing comparisons. Zero = price on request.
e.g. 34211 → 34 211 Kč/m²
priceSummaryCzk
number Summary display price. Typically identical to priceCzk but may differ for multi-unit developer projects.
priceUnitCb
object Price unit for priceCzk. {name, value}
1 = za nemovitost (total / per property)2 = za měsíc (per month)7 = za den (per day)
priceSummaryUnitCb
object Same structure as priceUnitCb. Typically identical — the summary unit for the display price.
Area figures (m²) are not present in the listing index — only in the full detail endpoint. The name field string contains them in human-readable form.
All location data lives in locality — a nested object with Czech administrative hierarchy and GPS coordinates.
locality.latitude
locality.longitude
number GPS coordinates. Precision depends on inaccuracyType — may be exact or approximate.
e.g. 49.808099, 15.404764
locality.inaccuracyType
string How precise the listed GPS point is.
address = exact building gps = GPS only, no address street = street-level ward = neighbourhood/area only
locality.city
string City or municipality. For Prague, always "Praha".
e.g. "Vlkaneč", "Praha", "Kladno"
locality.cityPart
string Sub-area within the city (district or borough). For Prague, this is the named neighbourhood.
e.g. "Záběhlice", "Nebušice", "Vinoř"
locality.district
string Czech administrative district (okres). Prague has inner districts like "Praha 4", "Praha 6". Regional districts e.g. "Praha-západ", "Kladno".
e.g. "Praha-východ", "Benešov", "Praha 4"
locality.region
string Czech administrative region (kraj).
"Hlavní město Praha" or "Středočeský kraj"
locality.street
locality.streetNumber
locality.houseNumber
string | null Street name, descriptive number (č.p.), and orientation number. Often null when inaccuracyType is not "address".
locality.quarter
locality.ward
string | null Finer administrative subdivisions used mainly within Prague (quarter = Praha X area). ward is rarely populated.
locality.zip
string | null Postal code. Frequently null in the listing index — available on the detail endpoint.
locality.geoHash
string Geohash encoding of coordinates. Useful for spatial proximity queries and clustering without a full geo database.
e.g. "u2fgqe33jn" (≈ 38m precision)
locality.entityType
string The geographic entity this locality record describes: addressstreetwardmunicipality
locality.*Id fields
number | null Numeric IDs for city, district, region, etc. (municipalityId, districtId, regionId…). Use these for filtering API requests — more reliable than string names.
locality.*SeoName fields
string | null URL-safe slugs for each geographic level. Used to build search URLs: /hledani/domy/{citySeoName},{regionSeoName}
The images[] array — each listing returns 5–40+ images with room-type classification codes.
images[].url
string Relative URL — prepend https: to use. CDN path includes size/quality params.
e.g. https://d18-a.sdn.cz/d_18/…/9fe9.jpeg
images[].restbType
number Room/photo type code. Allows filtering by room before fetching the full detail.
0 = interior1 = kitchen4 = bedroom5 = exterior/facade6 = garden8 = bathroom10 = storage/utility11 = garage12 = attic15 = ground floor plan16 = upper floor plan17 = aerial/drone19 = aerial photo22 = living area26 = land/plot29 = property exterior30 = neighbourhood
images[].order
number | null Display order override. When null, use array index order. A non-null value means the seller or agent manually reordered the gallery.
The first image (images[0]) is always the hero/thumbnail. The sreality CDN supports image resizing via URL path params — the c_img_qB_C segment encodes crop and quality.
Agency/seller info is split between the premise object and top-level premiseId / premiseLogo fields.
premiseId
number Unique agency ID. Use to fetch all listings by a specific agency or to deduplicate cross-portal listings.
premiseLogo
string Agency logo URL. An empty string "" means the listing is from a private seller (no agent), which is common on Bezrealitky cross-listed entries.
premise.seoName
string Agency slug — used to link to the agency's page on sreality.
e.g. "soukup-partners-s-r-o", "engel-volkers"
premise.citySeoName
premise.wardSeoName
premise.quarterSeoName
string Location of the agency office — not the property. Useful only for building the agency profile link.
e.g. the property is in Vlkaneč but the agency office is in "kolin"
Top-level pagination envelope and search metadata returned alongside results[].
pagination.total
number Total listings matching the search query — excluding promotional/sponsored slots.
e.g. 5624
pagination.totalWithPromo
number Total including promoted/boosted listings injected into the results stream.
e.g. 5892 (+268 promo)
pagination.limit
number Results per page. Typically 20 or 22. Controllable via per_page query param.
pagination.offset
number Current page offset (how many items skipped). offset = page × limit.
searchTitle
string Human-readable summary of the active search.
"Domy Praha, Středočeský kraj"
timestamp
ISO string When the response was generated. Use for cache invalidation and change detection in your scraper.
"2026-05-14T21:44:07.346Z"
regionTip / projectTip
/ brokerTip
object | null Editorially-selected promoted listings injected alongside the main results. Structurally identical to a normal result. Flag or skip these in your scraper — they may not match your search criteria.
